# Regista

**Regista directs every touch.** Every touch. Every replay. Every player. Found instantly.

*Regista* (Italian, "director"): the deep-lying playmaker who sees the whole pitch and directs every move, and the
word for a film director. Both meanings are the product.

Regista is a multi-agent system built for the Microsoft × Premier League **Inside the Game: Developer Hackathon**
(October 2026). Give it a football match and it does four things:
- finds every moment each player is on the ball, plus every replay and highlight they appear in;
- cuts, labels, explains and recaps those moments;
- lets anyone find them by asking: *"find me his nutmegs"*;
- turns uploaded matches into a catalogue where scouts compare players below the professional level, each against
  their own level.

All data is synthetic and generated by Regista: every player, club and competition is invented.

## How it works

```
 video ──▶ VISION AGENTS (private) ───────────▶ event stream ──▶ INTELLIGENCE AGENTS (public) ──────────▶ app
           shots · identity (kit number) ·       the contract     clips · labels · review · recap ·        Clips · Scout
           "is this you?" · possession ·         data/synthetic/  persist · index · profiles ·             Player · Studio
           events                                README.md        Librarian, Scout agent (Foundry + MCP)
```

- **Two Microsoft Agent Framework workflows** of distinct agents with typed handoffs, shared state, retries,
  dead-letter routing, checkpoints and a human in the loop. The vision layer is trained on Regista's own rendered
  broadcast; the intelligence layer runs on the event stream that crosses the boundary.
- **Foundry agents** (`gpt-5-mini`) label clips, answer as the Librarian and the Scout agent, and can write recaps.
  They call two MCP servers: **Regista's own**, with clips, recaps, players and the catalogue, and **Microsoft's Azure
  MCP Server**, which reaches Azure AI Search. Every Foundry answer falls back to Regista's rules, and says so, when
  Foundry is unavailable.
- **Identity is kit-number first**, never faces.
- **The catalogue:** the Regista League (England, semi-pro men, where Femi Toure is top scorer) plus 13 more invented
  competitions, from US college to U17 academies, men and women.
  - Every match carries who uploaded it and the camera.
  - Percentiles compare players only within their tier, age group, gender and position, and every number names its
    pool.
  - Small pools and noisy samples are flagged.

More detail: [docs/architecture.md](docs/architecture.md), [docs/workflow.md](docs/workflow.md) (the workflow graph),
[docs/vision.md](docs/vision.md).

## Microsoft and Azure: what runs

| Technology | In Regista |
|---|---|
| **Microsoft Agent Framework** | The vision and intelligence workflows (`regista.vision.agents`, `regista.agents.workflow`) |
| **Microsoft Foundry** | Label, Librarian, Scout and recap agents; traced in Foundry |
| **Azure MCP Server** + Regista's MCP server | Tools for the Foundry agents, both started inside the container |
| **Azure Container Apps** | The app. An event-driven **Container Apps Job** (KEDA queue scaler) runs the vision agents on uploads |
| **Azure Blob Storage, Storage queue** | Uploaded footage, processed matches and the private vision models; the job queue |
| **Azure Cosmos DB, Azure AI Search** | Matches, clips, labels and human verdicts; the clip index |
| **Application Insights** | OpenTelemetry spans for every agent, model call and tool call |
| **Microsoft Fabric** | The league and the catalogue as Delta tables in a lakehouse. Two Spark notebooks recompute Regista's numbers from the raw tables: 756 of 756 and 7,399 of 7,399 rows match |
| **GitHub Actions, Microsoft Entra ID** | Tests, image build, in-image smoke test and deploy with a federated identity (no stored secret). The app reaches Azure through Entra ID roles with key login switched off. The remaining secrets are the write key, the Studio view key and the Application Insights connection string |

**Planned, not wired:** Azure AI Vision, Video Indexer, Speech and Translator. The app is English only.

**Not used:** GitHub Copilot. Regista is built with Claude Code.

## Synthetic data, and how it is checked

- **A generator** writes full matches: possessions, passes, shots, substitutions, penalties, aerial duels, cards and
  offsides, with every player moving at 10 Hz within their own pace. Hidden player ratings drive outcomes; no API, MCP
  tool or page serves them. Every fixture is pinned by hash and generates the same on macOS and Linux.
- **A 2D broadcast renderer** with director cuts, replays and close-ups gives exact ground truth for the vision layer.
- **Realism:** the league sits inside Premier League per-90 and physical bands ([docs/realism-report.md](docs/realism-report.md)).
  Each catalogue level is checked only against what a published source supports
  ([docs/catalogue/realism.md](docs/catalogue/realism.md)).
- **Vision**, measured on matches it never saw (rendered footage): clip recall 0.75, precision 0.94. On a full
  90-minute match it found all 5 goals ([docs/vision.md](docs/vision.md)).
- **Fabric** recomputes the numbers independently ([docs/catalogue/fabric.md](docs/catalogue/fabric.md)).

## Run it yourself

```bash
pip install -e ".[dev,vision]"            # add ,cloud for Azure: ".[dev,vision,cloud]"
python3 -m pytest -q                      # 1,197 tests; -m slow for the whole-season ones
uvicorn regista.api:app                   # then open http://localhost:8000 (and /demo)
python3 -m regista.librarian data/synthetic/sample/syn_0294 "find me Castellanos doing a nutmeg"
python3 -m regista.mcp_server --list-tools
python3 -m regista.season build && python3 -m regista.season.metrics --rank goals
python3 -m regista.synth.report --league  # the league against Premier League bands
python3 -m regista.synth.report --catalogue   # each catalogue level against its sources
docker build -t regista . && docker run -p 8000:8000 regista
```

Azure setup is in [infra/SETUP.md](infra/SETUP.md). The event contract between the layers is in
[data/synthetic/README.md](data/synthetic/README.md). [CLAUDE.md](CLAUDE.md) is the project's source of truth and
records every decision.
