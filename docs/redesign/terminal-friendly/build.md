# The friendlier Scout terminal: the port

Synthetic data: invented players and clubs in the Regista League, generated by Regista.

Zaid approved the sandbox's "intuitive" round (the 15 changes in `sandbox/terminal-notes/intuitive-build.md`, plus the
fixes from its check and three review passes) and asked for it to be ported into the live Terminal (`/scout#terminal`) as
a pull request, with the reviewer's last open finding fixed: questions such as "most <stat>" and "<stat> per 90" worked
for a short list of stats only. This is that port, on branch `ux/terminal-friendly`. Nothing is merged or deployed.

## What changed, file by file

- `src/regista/static/scout/terminal.js`: rewritten on the app's version. It keeps the app's data layer (the real API,
  every moment paged in, the stale-command guard, `Regista.store`) and takes the sandbox's interface.
- `src/regista/static/scout/terminal-words.js` (new): reads the search box. It is pure: no page, no network, no storage.
  terminal.js gives it the league and runs the intent it returns (`rankKey`, `cmp`, `stat`, `many` and so on). Because it
  is pure, the tests run it in node against the API's real catalogue and the league's real players.
- `src/regista/static/scout/terminal.css`: the sandbox's stylesheet, re-scoped to `.pf .tx`. It keeps the app's additions
  (`--top-h` for the sticky bars, the loading and error text, heading specificity under the dashboard's styles).
- `src/regista/static/scout/index.html`: the new markup:
  - a search row (search box and the selected player)
  - example chips
  - one line of panel buttons, with "Layouts & notes" on phones
  - the phone panel row
  - the footer note
  - the clips drawer
  - `terminal-words.js` loads before `terminal.js`
- `src/regista/terminal_api.py` and `season/metrics.py`: a read-only addition. Each cell of `/api/terminal/screen`, and
  each scatter point (`x_evidence_total`, `y_evidence_total`), now says how many moments are behind the number. This is
  the `total` the evidence endpoint would list, worked out by the new `SeasonMetrics.evidence_total`, without building
  the list. The table needs it to show "▶ 5 moments" and to draw a number with nothing behind it as plain text.
- `src/regista/static/scout/scout.js`: the "Reset this demo" note now says "saved layouts" instead of "workspaces".
- `tests/test_scout_terminal.py`: updated for the new names and structure, with new tests (see below).
- `CLAUDE.md` §2.10: one bullet about this branch.

## The 15 changes, in the app

1. **Search box.** A magnifier icon, the placeholder "Search a player, club or stat…", ⌘K, and a yellow Search button. There is no
   CMD> and no <GO>. Plain commands work (`rank forwards goals`, `compare Toure and Ustinov`, `plot npxG against xA`,
   `similar to Toure`, `touch map Toure`, `highlights Toure`), and so do the old mnemonics (RANK, CMP, SCAT, SIM, HL,
   SHOT, FORM, HEAT, RDR, TEAM, HELP). Suggestions are labelled Command, Player, Club, Stat and Position. The status line
   answers in sentences ("Forwards ranked by Non-penalty goals: 18. Top: Femi Toure, 1.64 per 90.").
2. **Plain panel names.** The panel buttons read Players, Player, Radar, Clips, Shots, Touch map, Form, Scatter, Team and
   Help. Each tooltip gives the shortcut ("Players: go to it (Alt+1)"), as does `aria-keyshortcuts`. A hidden panel's
   button is dashed and says "is hidden: show it".
3. **Help** lists the commands as plain words, each with an example to click, including a "question" row. One line lists
   the short forms that still work.
4. **"Saved layouts: 1 2 3"** and **"Reset layout"**. The messages say "Switched to layout 2, which was empty, so it starts
   from the default (changes save automatically)" and "Layout 1 reset to the default".
5. **"Selected: Femi Toure BRO · FW · #9"** with **Compare with…**. That button fills the box with "compare Femi Toure, "
   and suggests players other than the ones already named. While comparing, the line shows "Comparing:" with chips and
   Clear, or "Add <full name> to the comparison (replaces …)". The player card has the same button.
6. **Plain wording.** The column toggle says "Percentile". The filter says "Regulars only (101+ minutes)". The card tag says
   "Regular", and the scatter checkbox says "Include non-regulars". Tooltips say "percentile among regular forwards". The
   header legend "≈ small sample, read with care" opens a short note in plain words (the sample note is reworded:
   "regular", not "qualified"; ≈, not "noisy"; no module name).
7. **Panel controls.** Move, size and close are SVG icons. They show on hover and on keyboard focus, and always on touch
   screens. Each has a tooltip and an accessible name ("Form: small, make it medium"); an arrow that cannot move is
   disabled. Column headers lost their ▼ and ×. A click sorts, a second click reverses, and the sorted column is
   underlined in yellow. The panel header says "Sorted by NP goals, highest first". Columns are removed in a **Columns (8)** menu,
   which also holds "Add a stat…" and "Default columns". The menu stays open while columns are removed and closes on
   Escape or a click outside it.
8. **Order.** The search and the selection sit on top. The players table is on the left, with the player card and radar
   stacked on its right. Under the table, `fitTall` moves up as many of the next panels (two to a row) as leave the least
   empty space. Below that, `fillRows` widens each row to the full 12 columns. At 1440 px the default comes out the same
   as the sandbox's final measurement:

   | Panel | Top (px) | Where |
   |---|---|---|
   | Players table | 214 | left |
   | Player card | 214 | right |
   | Radar | 988 | right |
   | Form, Shots | 819 | under the table |
   | Touch map, Scatter | 1408 | under the table |
   | Team | 1906 | full width |

9. **Clips is a drawer** on the right, and a bottom sheet at 720 px and narrower. There is no Clips panel any more. The
   first number moves focus to the drawer's heading. Escape or Close puts focus back on the number, or on the same number
   after a repaint. While the drawer is open, later numbers only change what it plays. Alt+4 and the Clips button open and
   close it. While a long list loads, the drawer says "Loading every moment behind this number…".
10. **One compact header line.** The synthetic-data note is said once, at the bottom ("Synthetic data: invented players
    and clubs in the Regista League, generated by Regista."), built from the catalogue's note.
11. **Short column labels** ("NP goals", "NP xG/shot", "Prog. received", "Tkl + int (adj.)" and so on). Labels of up to 12
    characters stay on one line, and longer ones wrap to two at most. The full name, definition, rule and source are in
    the tooltip on hover and focus, and the full name is the header's accessible name.
12. **Clickable numbers look clickable.** They have a solid underline. On hover or focus a ▶ appears and the underline
    turns yellow. The tooltip ends "▶ 5 moments · click to play" ("· Enter plays them" in the table). Accessible names say
    "play its 5 moments". The count is the API's `evidence_total`: every moment the drawer will play, never capped.
13. **Example chips:** Best finishers, Compare Toure and Ustinov, Who plays like Toure?. Each chip's tooltip shows the
    command it runs, and a chip keeps focus after it runs.
14. **A row click selects the player.** The card has **Open profile →**, which links to `/players/{id}` for every player
    (the app has a page for all of them).
15. **Sticky panel row on phones.** It sits under the header (`top: var(--top-h)`). A tap brings that panel's top up just
    under the row and marks the panel as current. Clips opens the bottom sheet. On phones only Help stays in the
    panel-button row.

## The sandbox reviewers' fixes, carried over

- **Plain questions work:**
  - "who are the best finishers?", "top scorers", "best dribblers in midfield"
  - "forwards", "strikers"
  - "Toure shots", "Toure goals", "Toure highlights"
  - "Toure vs Ustinov", "compare Toure with Ustinov", "who is better Toure or Ustinov"
  - "best finishers at Brookfield", "who scores the most", "show me Toure"

  Namesakes resolve in a set order: the selected player, then players they play like, then the same position when
  comparing, then players in the current table, then most minutes. So "Ustinov" next to Toure means Amari.
- **Per 90 is said where people read.** The table caption says "values per 90 minutes (except %, averages and totals)",
  season counts say "(total)", the status line says "1.64 per 90", and the metric tables mark "/90" and "total".
- **A number with nothing behind it is plain text.** It has no underline, no ▶ and no pointer. Its tooltip and accessible
  name say so, and a click explains on the status line instead of opening an empty drawer. Team numbers do the same when
  a shot-based total is 0.
- **No gap on wide screens:** `fitTall` and `fillRows`, as above.
- **The phone's first screen shows the table:**
  - "Layouts & notes" folds the saved layouts and the note away.
  - The selection and the chips scroll sideways on one row each.
  - Club and position sit on a second line under the name, so the ranked stat shows whole.
- **Saved-layout wording:** the messages above.
- **Removing the sorted column** re-sorts by the first remaining column and says so ("Removed Non-penalty goals; the
  table is now sorted by Non-penalty xG.").
- **Radar labels** use short labels with the full name on hover. A test checks that every short label a radar can show
  fits in 18 characters. This test found one more long label, "Keeper pass completion", now "Keeper pass %".
- **Highlights:** `highlights <player>` (also HL, "Toure clips", "watch Toure", and the card's Highlights button). It
  plays one reel: goals, assists and saves first, then other shots, chances made, skills and defending. Each clip appears
  once. In the app every moment of each stat is read through the API, not the first 10.

## The "most <stat>" fix (Zaid)

Before, the words a question started with ("who has", "most", "best", "per 90") were stripped, and the rest went only to
a short synonym list. So `most xG`, `xG per 90`, `top 5 xG`, `most key passes`, `most touches in the box`, `best save
percentage` and `most minutes` all answered "Nothing found".

Now, in `terminal-words.js`:

- **Every stat has three names** that the box knows exactly: its key, its label and its short column label. They are
  compared in a loose form: case, accents and punctuation are ignored, and "percent", "percentage" and "pct" all read as
  "%".
- **A question is tried as a stat name** after each of its opening words is read off ("who has", "the", "most", "top",
  "5", "per 90"). This happens before position and club words are looked for, since some stat names contain them
  ("Keeper passes", "On-pitch goals for").
- **When a question still names no single stat**, the start-of-word match runs too. If several stats match (for example
  "tackles", or "Whitfield tackles"), the status line offers each one as a button.
- **A command word that is also the start of a stat name** ("shots", "shots on target", "shots per 90") means the stat,
  unless a player follows ("shots Toure"). The mnemonic SHOT always means the shot map.
- **A goalkeepers-only stat** (save %, clean sheets) ranks the goalkeepers unless the question names a position.
- **"most minutes"** sorts the table by minutes played.

The tests run 13 phrasings (the stat alone, "most …", "the most …", "who has the most …", "… per 90", "top 5 …",
"highest …", "best …", "rank …" and others) on every one of the 127 metrics, by each of its names. All of them reach that
metric. Another test checks that no two metrics share a name; this caught "Passes, final third" (a short label) against
the key `passes_final_third`, and the short labels are now "Passes in final third", "Passes from defensive third" and so
on.

## Kept from the app (it was ahead of the sandbox)

- **The real API only.** Nothing is read from an export file, and the terminal writes nothing to the server.
- **Complete evidence.** Every page is read (`evidence_offset`), and no "first 10" appears anywhere.
- **The four fixes from the first port:**
  - A form bar counts every moment of its match.
  - The radar breaks at a missing percentile, and its note says why a player is not drawn.
  - Alt+1 goes straight into the table, with the leader's ranked number as the active cell.
  - Commands bring their subject into view after the status line is written, once every shown panel has settled.
- **The stale-command guard.** Every command and every hand-picked player bumps `gen`, and a command that is no longer
  current drops its line and its scroll. This now also covers a ranking still waiting for its column, highlights, a
  player's stat, and the "Playing …" line of a list that finishes loading after a newer command.
- **"Reset this demo" resets the Terminal** in the same tab and in other tabs, and now also stops what is playing and
  closes the drawer.
- **Per-visitor state only through `Regista.store`.** Saved layouts moved to version 3 and version 2 still loads: a
  layout that was still the v2 default takes the new default, and a changed one keeps its order, sizes and hidden panels
  without Clips. Its players, comparison, columns, sort and filters carry over. I checked this in the browser with a
  stored v2 default and a changed v2 layout.
- **Every /scout inventory item.** The Terminal is still a section of /scout, its own panels use `data-txp`, never
  `data-panel`, and the rest of /scout is untouched apart from one sentence in Settings.
- **The app rules hold:**
  - No inline script, handlers or `style=` in markup; data colours, widths and grid spans go through `element.style`.
  - `esc()` is applied to every API value that reaches innerHTML.
  - The hidden ratings never appear.

## Two small improvements found while checking

- **Panels left on "Loading…" in a hidden tab.** A panel whose data arrived while the tab was hidden stayed on
  "Loading…". The batched repaint waited for an animation frame, and hidden tabs get none. It now waits for a frame or
  100 ms, the same way `panelsSettled` already did.
- **Tooltips over the rows after a mouse click.** A tooltip opened by keyboard focus is now shown only after keyboard
  input. Clicking Close used to leave a tooltip over the next rows (a pass-3 nit).

1440 and 375).

  - an unknown word

  - Compare with… fills "compare Amari Ustinov, " and suggests other players.

**At 375:**
- The first table row is on the first screen, and club and position sit under the name.

**Tests:** `python3 -m pytest -q`: 849 passed (13 deselected). The new tests in `tests/test_scout_terminal.py` cover:
- every metric by every name in every question form (node, real catalogue and players)
- names unique across metrics
- radar labels that fit
- plain questions and mnemonics read as the right intents
- the intents terminal.js runs
- `evidence_total` on the screen and the scatter, checked against the evidence endpoint
- zero numbers as plain text
- panel names, shortcuts and the drawer
- v2 layouts loading
- the header, examples and profile link
- the phone row and the panel controls' CSS

**Limits:** the browser pane was hidden for part of the run, so I read positions with scripts and waited for smooth
scrolls to finish. I did not test with a screen reader.
